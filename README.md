# HydroCompass — MVP

A working base version of the water resource intelligence platform: synthetic
data → trained forecasting models → FastAPI backend → React frontend. Built
to be extended incrementally (swap in real data, upgrade models, add pages)
without a rewrite.

## What's included

- **Synthetic data generator** (`backend/data_generator.py`) — produces
  internally-consistent regions, climate history, demand history, reservoirs,
  and reservoir history (2010–2025), with realistic relationships (population
  growth → demand, rainfall/temperature → agricultural demand and inflow).
- **Training pipeline** (`backend/train_models.py`) — trains and saves a
  demand-forecasting model and an inflow-forecasting model with scikit-learn
  (`RandomForestRegressor`, drop-in swappable for XGBoost later).
- **FastAPI backend** (`backend/app`) — loads the trained models once at
  startup and exposes REST endpoints for regions, reservoirs, demand
  forecasts, scenario simulation, national overview, and a risk map.
- **React frontend** (`frontend`) — 5 pages (Overview, Demand Forecast,
  Reservoirs, Scenario Simulator, Risk Map) built with Vite, Tailwind,
  Recharts, and Leaflet.

## Architecture

```
React (Vite)  →  FastAPI  →  ML models (scikit-learn) + water-balance simulation
                           →  CSV data (swap for PostgreSQL later)
```

Per the "don't predict what you can calculate" principle: the ML models only
predict **demand** and **inflow**. Reservoir **storage** is derived from a
water-balance calculation (`storage_next = storage + inflow - release`) in
`backend/app/simulation.py`, not predicted directly — this keeps the system
physically grounded and easy to explain in a demo.

## Running it

### 1. Backend

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt

python3 data_generator.py     # generates backend/app/data/raw/*.csv
python3 train_models.py       # trains + saves backend/trained_models/*.pkl

uvicorn app.main:app --reload --port 8000
```

API docs (Swagger UI): http://localhost:8000/docs

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173 — the Vite dev server proxies `/api/*` to
`localhost:8000`, so both must be running.

## Extending it (suggested order)

1. **Swap synthetic data for real data.** Replace the CSVs in
   `backend/app/data/raw/` with real historical records in the same schema,
   then rerun `train_models.py`. Nothing else needs to change.
2. **Move CSVs into PostgreSQL + PostGIS.** Only `backend/app/store.py` needs
   to change — it's the single place that loads data.
3. **Upgrade models.** `train_models.py` uses scikit-learn's
   `RandomForestRegressor`; swapping in XGBoost is a same-interface change
   (`model.fit(X, y)` / `model.predict(X)`).
4. **Add authentication, a real map basemap license, and error boundaries**
   before treating this as production-ready — the current CORS policy
   (`allow_origins=["*"]`) is intentionally permissive for local development
   only.
5. **Add the Recommendations page** as its own route (currently
   recommendations are shown inline on the Scenario Simulator page — this
   was a deliberate MVP simplification since they're generated by the same
   `/api/scenario/simulate` call).

├── backend/
│   ├── data_generator.py
│   ├── train_models.py
│   ├── requirements.txt

│   └── app/

│       └── api/
│           ├── regions.py
│           ├── reservoirs.py
│           ├── forecast.py      POST /api/forecast/demand

└── frontend/
    └── src/
